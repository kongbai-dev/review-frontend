# 文档管理页后端更新改造方案

更新时间：2026-05-17
适用项目：`review-frontend`
对应后端文档：
- `D:/pythoncodes/AI_TCAD/testagent/backend_api/docs/v1_documents_batch_sync_api_spec.md`
- `D:/pythoncodes/AI_TCAD/testagent/backend_api/docs/v1_documents_upload_modes_api_spec.md`

## 1. 目标

本次改造目标是让前端文档管理页与后端最新的 `documents` 契约保持一致，同时尽量不破坏现有文档列表、筛选、下载与审核主流程。

重点包括：

1. 明确拆分三条上传链路。
2. 接入单文件上传的 `metadata_mode`。
3. 接入 file-only 批量直传链路。
4. 逐步把文档批处理与批量 QA 能力迁回与后端一致的任务模型。

## 2. 后端关键变化

### 2.1 单文件上传

接口仍为：`POST /api/v1/knowledge/documents`

关键变化：

1. `upload_mode` 仅允许 `sync`。
2. 新增 `metadata_mode`：
   - `auto`
   - `csv_required`
   - `file_only`
3. 单文件上传时，`metadata_csv` 不再要求与文档文件同名。
4. `sync` 上传不再接收 `subdir`，也不会读取 CSV 中的 `subdir`。

### 2.2 批量上传拆分为两条链

#### A. 文档 + CSV 配对链

1. `POST /batch-upload/doc-files`
2. `POST /batch-upload/csv-files`
3. `GET /batch-upload/session/current`
4. `POST /batch-sync/start`

#### B. file-only 直传链

1. `POST /batch-upload/direct/doc-files`
2. `GET /batch-upload/direct/session/current`
3. `POST /batch-sync/direct/start`
4. `GET /batch-sync/tasks/{task_id}`

### 2.3 QA 任务模型

1. 单文档仍支持：`POST /qa-generation/start`
2. 新增多文档批任务：
   - `POST /qa-generation/batch-start`
   - `GET /qa-generation/batch-tasks/{batch_task_id}`

## 3. 当前前端与后端不一致点

当前文件：

- `src/components/business/DocumentUploadPanel.vue`
- `src/services/api/document.api.ts`
- `src/stores/document.store.ts`
- `src/pages/DocumentManagePage.vue`

主要不一致点：

1. 单文件上传仍强制要求 `文档 + 同名 CSV`。
2. 单文件上传仍保留 `subdir` 输入与提交。
3. 上传工作台只有 `sync` 与 `doc/csv 批量配对` 两种概念。
4. 尚未接入 `direct` file-only 批量直传链。
5. 主页面顶部的“批处理同步”只有一套语义，无法区分配对链与直传链。
6. 多选区仍只支持单文档 QA 生成。

## 4. 改造原则

1. 文档列表区保持稳定，仍以表格为主。
2. 上传工作台承担复杂上传流程，不把主页面继续做重。
3. UI 要让用户明确知道自己当前走的是哪条链路。
4. 批量任务统一以 `task_id` 或 `batch_task_id` 轮询，不假设上传成功等于处理完成。

## 5. 页面改造方案

### 5.1 文档管理主页面

保留：

1. 列表、筛选、下载、勾选。
2. 上传工作台弹窗入口。
3. 单文档/多文档 QA 区域。

后续阶段调整：

1. 顶部“批处理同步”按钮从主页面迁出。
2. 改为在上传工作台内部针对不同链路分别启动同步。

### 5.2 上传工作台弹窗

改为三页签：

1. `单文件上传`
2. `批量上传（文档+CSV 配对链）`
3. `批量直传（file-only）`

#### 页签一：单文件上传

表单项：

1. `knowledge_base`
2. `file`
3. `metadata_mode`
4. `metadata_csv`（按模式显示或禁用）
5. `document_type`
6. `title`

规则：

1. 默认 `metadata_mode=auto`。
2. `csv_required` 时必须选择 CSV。
3. `file_only` 时不允许选择 CSV。
4. 去掉 `subdir`。
5. 去掉“文档与 CSV 同名”的硬校验。

#### 页签二：批量上传（文档+CSV 配对链）

操作项：

1. 上传文档。
2. 上传 CSV。
3. 刷新 session。
4. 启动批同步。

展示项：

1. `doc_file_count`
2. `csv_file_count`
3. `paired_count`
4. `unpaired_count`
5. `unmatched_documents[]`
6. `orphan_csv_files[]`
7. 最近一次任务状态

规则：

1. 保留批量 CSV 文件名 `_csv` 去尾逻辑。
2. `strict_pairing` 仍使用配置文件，不交给 UI。

#### 页签三：批量直传（file-only）

操作项：

1. 上传文档。
2. 刷新 direct session。
3. 启动 direct 批同步。

展示项：

1. `doc_file_count`
2. `paired_count`（解释为 ready-to-sync）
3. `unpaired_count`（固定 0）
4. 最近一次任务状态

规则：

1. 不出现 CSV 上传区域。
2. 不显示 orphan CSV 说明。
3. 仅允许文档文件上传。

## 6. 数据层改造方案

### 6.1 `src/types/domain.ts`

新增或调整：

1. `MetadataMode = 'auto' | 'csv_required' | 'file_only'`
2. `UploadMode` 扩展为支持 `batch_direct`
3. `UploadSyncDocumentPayload.metadata_csv` 改为可选
4. `UploadSyncDocumentPayload` 增加 `metadata_mode`
5. 删除 `UploadSyncDocumentPayload.subdir`
6. 为 direct session / direct upload 复用现有批量类型

### 6.2 `src/config.ts`

新增 endpoint：

1. `DOCUMENT_BATCH_UPLOAD_DIRECT_DOC_FILES`
2. `DOCUMENT_BATCH_UPLOAD_DIRECT_SESSION_CURRENT`
3. `DOCUMENT_BATCH_SYNC_DIRECT_START`

后续阶段预留：

1. `DOCUMENT_DETAIL`
2. `DOCUMENT_DELETE`
3. `DOCUMENT_QA_GENERATION_BATCH_START`
4. `DOCUMENT_QA_GENERATION_BATCH_TASK`

### 6.3 `src/services/api/document.api.ts`

第一阶段需改：

1. `uploadSyncDocument` 支持 `metadata_mode`
2. `metadata_csv` 改为可选
3. 不再提交 `subdir`
4. 新增：
   - `batchUploadDirectDocFiles`
   - `getCurrentDirectBatchSession`
   - `startDirectBatchSync`

### 6.4 `src/stores/document.store.ts`

第一阶段需改：

1. 新增 `batchUploadDirectDocResult`
2. 新增 `currentDirectSessionSummary`
3. 新增 direct 链路 action：
   - `batchUploadDirectDocs`
   - `refreshCurrentDirectSessionSummary`
   - `triggerDirectBatchSync`

## 7. Mock 对齐方案

因为当前项目默认 `USE_MOCK=true`，第一阶段必须同步更新 `src/services/mock/document.mock.ts`，否则本地联调会与 UI 新流程不匹配。

需要支持：

1. 单文件 `metadata_mode` 三种模式。
2. direct 批量直传 session。
3. direct 批同步任务。

## 8. 分阶段实施顺序

### 第一阶段：上传工作台重构

目标：

1. 三页签工作台。
2. 接入 `metadata_mode`。
3. 接入 `direct` 直传链。
4. 删除 `subdir`。

落地文件：

1. `src/components/business/DocumentUploadPanel.vue`
2. `src/services/api/document.api.ts`
3. `src/stores/document.store.ts`
4. `src/services/mock/document.mock.ts`
5. `src/types/domain.ts`
6. `src/config.ts`

### 第二阶段：批量 QA 对齐

目标：

1. 多文档 `batch-start` 接入。
2. 文档多选区升级为真正批量 QA。

### 第三阶段：主页面动作收口

目标：

1. 去掉主页面模糊的单一“批处理同步”。
2. 把批同步操作完全迁回上传工作台。

### 第四阶段：详情与删除

目标：

1. 接入 `GET /documents/{document_id}`
2. 接入 `DELETE /documents/{document_id}`
3. 做详情抽屉/弹窗与删除确认流

## 9. 第一阶段验收标准

1. 单文件上传支持：
   - 有 CSV 的 `auto`
   - 强校验 `csv_required`
   - 无 CSV 的 `file_only`
2. 文档与 CSV 不再强制同名。
3. `subdir` 不再出现在 UI 和请求体中。
4. 批量直传链在 mock 与真实 API 下都可调用。
5. 上传工作台能独立展示：
   - 配对链 session
   - direct 链 session
   - 最近一次批同步任务状态
